# 開発ルール

AI（Claude Code）に作業を頼むときの取り決めです。
AI はこのルールを守って作業します。

---

## 1. 推測で修正しない
必ず実際のコードを確認してから判断する。

## 2. 一度に大量解析しない
全ファイルスキャンを避け、必要な範囲だけ読み込む。

## 3. 一度に1テーマ
バグ修正・機能追加・整理・デザイン変更を同時に行わない。

## 4. 最小差分
必要以上にコード全体を書き換えない。

## 5. 既存仕様を守る
依頼していない見た目・操作感・バランス・UI・仕様を変更しない。

## 6. 承認制
変更前に以下の7項目を説明し、承認を待つ。

1. 現状
2. 原因
3. 修正方針
4. 変更ファイル
5. 影響範囲
6. リスク
7. 確認方法

## 7. 勝手に削除しない
不要・重複・古いと思われるファイルも、承認なしで削除しない。

## 8. 復元可能にする
重要な編集前は Git の状態やバックアップを確認する。

## 9. GitHub Pages を前提にする
ローカルだけでなく、公開URL・iPhone Safari・Instagram 内ブラウザでも動く構成を意識する。

## 10. ドキュメント化
重要な仕様・バグ・TODO・アイデア・変更履歴は `docs/` 配下の適切な Markdown へ反映する。

## 11. 小出しの追加依頼をしない
必要な内容は最初から指示・提案・生成物へ統合する。
何度も追加入力をさせない。

## 12. 初心者対応
操作が必要な場合は、**何を・どこで・なぜ**行うかを具体的に説明する。

---

## どのドキュメントに何を書くか（ルール10の運用）

| 内容 | 書く場所 |
|------|---------|
| 仕様・現在の作り | [SPEC.md](SPEC.md) |
| 変更した記録 | [CHANGELOG.md](CHANGELOG.md) |
| やりたいこと・アイデア・課題 | [TODO.md](TODO.md) |
| 公開まわりの手順 | [DEPLOY.md](DEPLOY.md) |
